# LUVN synthetic hackathon data

All content is **synthetic**: invented LUVN-area cohorts and texts generated by
a language model from them. No real persons. Every text still requires human
review before any use beyond experimentation.

## Contents

The release is organised by **cohort first**. Pick one cohort folder: its
texts sit next to the tables they join to.

```
2025/                                       one-year cohorts (2025)
  clinical/tables/                          frozen clinical_2025 tables + link tables
  clinical/text/clinical-notes.*            2,976 visit notes
  social/tables/                            frozen social_2025 tables
  social/text/social-notes.*                1,500 decisions and plans
2024-2026/                                  three-year cohorts, SAME PEOPLE in clinical and social
  clinical/tables/                          frozen clinical_2024_2026 tables + link tables
  clinical/text/clinical-notes.*            1,500 visit notes, one per linked person
  social/tables/                            frozen social_2024_2026_clinical_linked tables
  social/text/social-notes.*                the same 1,500 people's decisions and plans
docs/
  clinical_schema_guide.html                guide to all clinical tables and texts (Finnish/English)
  social_schema_guide.html                  guide to all social tables and texts (Finnish/English)
USAGE.md                                    quick start and things to know
examples/                                   Python (Polars, pandas), DuckDB SQL and R examples
```

Each text file comes as `.parquet`, `.jsonl` and `.csv`. See
[USAGE.md](USAGE.md) for how to load and join the data.

- **`2025/` and `2024-2026/` are independent** datasets with their own
  identifiers. Do not combine them.
- **In `2025/`, clinical and social are separate populations** and cannot be
  linked.
- **In `2024-2026/`, clinical and social share the same 15,000 people** (same
  `asiakas_id`), so one person can have both health-centre and social-care
  records and texts.

## Formats

Every dataframe and table comes in three formats with identical content:

- **Parquet**: typed columns (dates as `date`); preferred for Polars/pandas.
- **JSONL**: one JSON object per line, UTF-8; dates as `YYYY-MM-DD` strings,
  missing values as `null`.
- **CSV**: UTF-8 without BOM, comma-separated, header row; dates as
  `YYYY-MM-DD`; missing values are empty fields. Note texts are quoted and
  contain line breaks: use a CSV parser that supports quoted multi-line fields.
  The tables also have a `*.schema.json` type description; use those types
  when reading CSV.

Pick one format per table; the copies are not additional records.

## Tables: `<cohort>/*/tables/`

Unchanged copies of the business tables from four frozen cohorts
(`projects/frozen_datasets.json`): three frozen on 2 October 2026 and the linked
social cohort frozen on 7 October 2026. The linked cohort replaces the
independent `social_2024_2026` cohort in this release; it has nearly the same
case storylines, attached to the clinical 2024–2026 people. Each table file
(CSV, Parquet, JSONL and `*.schema.json`) is byte-identical to the frozen
original. Only the business tables are included: the frozen bundles' manifests,
conversion records and `audit/` folders (simulation lineage, scenario context
and internal states) are not. The frozen bundles are identified by their
manifest checksums below.

**`osastohoitojakso` (inpatient episodes) is empty by design** in both clinical
cohorts: the simulation models outpatient health-centre care only, and the
generator requires that no inpatient episodes exist. The table is kept because
it belongs to the LUVN table contract, so code written against these files
also works with extracts that do contain inpatient episodes. Its files hold
the column structure only: a header-only CSV, a zero-byte JSONL, a zero-row
Parquet and a `schema.json` with `row_count: 0`.

`docs/clinical_schema_guide.html` and `docs/social_schema_guide.html`
describe every table in the delivery, including the link tables and the text
tables, with fields, types, keys and row counts for both cohorts. They are
copies of the project guides with this delivery's contents and tables added.

## Link tables: `<cohort>/clinical/tables/*_kontakti.*`

The medication (`laakitys`) and laboratory (`vastausarkistohistoria_view`)
tables have no contact identifier in their contract. These tables give the
exact contact of every row. Row order follows the frozen table. They sit next
to the frozen tables in each `clinical/tables/` folder, with a `*.schema.json`
sidecar like the frozen tables; they are not part of the frozen bundles.

| File | Columns | Rows 2025 | Rows 2024–2026 |
|---|---|---|---|
| `laakitys_kontakti.*` | `laakitys_avain` (str) → `kontakti_id` (str) | 32,060 | 105,463 |
| `laboratorio_kontakti.*` | `Avain` (int) → `kontakti_id` (str) | 6,400 | 18,653 |

Derived from each cohort's `audit/record_lineage.parquet`, verified against the
frozen manifest (sha256 `793ad98f…a056ee` for 2025 and `20714f28…46a4ab` for
2024–2026). Every row matched exactly one lineage
record, and its contact exists in `kontakti` and belongs to the same
`asiakas_id`. Only the key and `kontakti_id` are included; the lineage scenario
labels are not.

```python
import polars as pl
med = pl.read_parquet("2025/clinical/tables/laakitys.parquet")
link = pl.read_parquet("2025/clinical/tables/laakitys_kontakti.parquet")
med_with_contact = med.join(link, on="laakitys_avain", how="left")
```

Social tables need no link tables: they join through `asiakas_id`,
`vireilletulo_id`, `selvitys_id`, `paatos_id` and `palvelu_id`.

## 2024–2026 texts: the same people in both domains

Texts for 1,500 people from the 2024–2026 cohorts, where the same person has
both health-centre and social-care records. Join them to
`2024-2026/clinical/tables/` and `2024-2026/social/tables/`, and to each other,
on `subject_id`.

| File | Rows | Columns |
|---|---|---|
| `2024-2026/social/text/social-notes.*` | 1,500 cases (one per person), 512 with a home-care plan | same as `2025/social/text/social-notes.*` |
| `2024-2026/clinical/text/clinical-notes.*` | 1,500 notes (one per person) | same as `2025/clinical/text/clinical-notes.*` |

- **People:** 1,500 social cases sampled from the linked social cohort,
  balanced by document type and scenario. Each person has one social case.
- **Clinical visit:** for each person, the visit closest to the social
  referral date (half before, half after; median 39 days apart).
- **Complete:** all 1,500 people have both a clinical note and a social text
  (two clinical notes needed extra retries before passing the checks).
- **No cross-domain mentions:** each text was generated from its own domain's
  facts only.
